# خطة إنهاء لوحة إدارة بيكو والمكاتب

تاريخ المراجعة: 2026-09-19. الحالة: **WAVE 0 — CONTRACTS VERIFIED / ACCEPTANCE SETUP PARTIAL**.

هذا الملف قائمة التنفيذ والقبول الخاصة بالداشبورد. نُفذ جرد الموجة 0 ومصفوفة الوصول، وأُعيد تشغيل مشروع Development وجُمع كتالوجه بقراءة فقط. لم تُطبق migrations أو تغييرات بيانات أو كود تطبيق. تجهيز حسابات القبول ما زال جزئيًا؛ انظر نتيجة الموجة 0 في نهاية الملف.

## 1. النتيجة الفعلية للمراجعة

الداشبورد ليست منتج إدارة مكتملًا جزئيًا؛ الموجود واجهة تأسيس صغيرة. يوجد باك إند قابل لإعادة الاستخدام، لكنه لا يغطي وحده صلاحيات موظفي المنصة، عمليات الإدارة، التقارير والتدقيق المطلوبة. إنهاء الشاشات دون هذه العقود لن يحقق قبول المنتج.

لا نضع نسبة إنجاز رقمية: وجود جداول أو نجاح build قديم لا يثبت اكتمال دورة عمل. نميز بين **موجود في المصدر**، **تحقق تاريخي موثق**، و**قبول حالي على بيئة التشغيل**.

## 3. فجوات يجب منعها قبل بناء الشاشات

1. **صلاحية المنصة ليست Super Admin فقط:** الدوال الحالية للمراجعة تستخدم `private.is_super_admin()`؛ تعريف أدوار Operations/Support/Verification في الواجهة وحده لن يمنح وصولًا صحيحًا. نضيف تفويضًا خادميًا بصلاحية ونطاق، مع الحفاظ على تصحيح Wave A وعدم تجميع صلاحيات مكتبين.
2. **التدقيق غير مكتمل:** `verified_by/verified_at` ليست تاريخًا غير قابل للمحو لكل مراجعة. و`order_events` لا يغطي الأدوار والإعدادات والمكاتب ولا يملك حاليًا منحة SELECT للمستخدم المصادق؛ timeline يحتاج عقد قراءة مخول أيضًا. `review_driver_verification` يطلب سبب التعليق لكنه لا يحفظه كما يحفظ سبب الرفض. يلزم سجل موحد بالتزامن مع التعديل نفسه وحفظ سبب التعليق ضمن ADM-15.
3. **وجود مفاتيح permissions لا يعني وجود العمليات:** لا توجد دورة ويب مكتملة لإنشاء/تعليق العملاء والمكاتب أو إدارة الموظفين والأدوار. لا نفتح DML مباشرًا لتجاوز ذلك.
4. **المراجعة الحالية ليست محرر حالات:** واجهة اعتماد السائق يجب أن تستدعي انتقالات محددة؛ مراجعة قيود الحالة الحالية/الجديدة مطلوبة قبل توسيع صلاحيات RPCs.
5. **المستندات تحتاج فصل metadata عن الملفات:** صف driver_documents قد يقرأه المكتب بصلاحية drivers.view، لكن ملفات Storage وصفوف motorcycle_documents محصورة حاليًا في المالك أو Super Admin. نحدد تفويض المعاينة والرفع بالنيابة ونختبر الروابط الموقعة بين الأدوار والمكاتب.
6. **عقود الموبايل ليست عقود الأدمن:** `get_driver_earnings` لسائق نفسه، والتتبع للعميل المالك، والطلب المستقل للمتقدم نفسه. لا ننتحل مستخدمًا لإعادة استخدامها.
7. **المالية ليست جاهزة للنشر:** D07 مصدر موجود دون قبول تشغيل حالي مثبت. شحن الرصيد يستقبل actor في عقد موثوق فقط؛ أي واجهة جديدة يجب أن تستنتج المنفذ من الجلسة وتحمي من تكرار الدفع عند إعادة الطلب.
8. **الإعدادات ليست JSON editor:** كل حقل مسموح يحتاج نوعًا وحدودًا ومستهلِكًا فعليًا وأثرًا معلومًا. لا نعرض إعدادًا يحفظ بنجاح ولا يغير التشغيل.

اختلافات الدوكس: عبارة `motorcycle_documents PENDING` في المواصفات القديمة تجاوزها M10؛ تسمية M10 تعني الداشبورد في roadmap والسلامة في تقارير التنفيذ؛ نسب العمولة حُسمت في Freeze وDEC-006؛ ratings مؤجلة وفق PRODUCT فلا نصنعها لتعبئة تقارير قديمة. بعض إعدادات dispatch/pricing موصوفة كمستقبلية رغم وجود تنفيذ لاحق. نسجل الحالة حسب الميزة والدليل، لا رقم المرحلة وحده.

## 4. حدود التنفيذ

- تطبيق واحد للأدمن والمكتب؛ Email + Password. لا تسجيل عام يمنح STAFF أو صلاحيات مرتفعة.
- CASH فقط، لا wallet ولا cash-out ولا payroll ولا BI متقدم ولا نظام تذاكر جديد.
- المكتب لا يعتمد السائق نهائيًا، ولا يرى مكتبًا آخر. الصلاحيات تنفذ في الباك إند بالإضافة إلى التنقل والأزرار.
- اختيار العرض للعميل؛ لا تعيين آلي ولا تغيير فائز يدوي عام ولا محرر حالة حر.
- نقل مكتب السائق بطلب وموافقة؛ الطلبات القديمة تحتفظ بمكتبها وحقائقها المالية وقت التنفيذ.
- عمولة المستقل والمكتب والعروض الترحيبية وفق Freeze وDEC-006؛ لا فرض عمولات رجعية على الطلبات القديمة، والقيم المفقودة تظهر «غير متاح».
- لا SQL محلي مطلوب من صاحب المنتج: الموجة 0 استخدمت Supabase Development لجرد قراءة فقط. لا يسمح الجرد بادعاء قبول سلوك العقود أو تطبيق التحديثات غير المطبقة.
- لا build أو lint للداشبورد لأن كودها لم يتغير. الموجة 0 أعادت تشغيل Development وقرأت الكتالوج فقط؛ لا تعديل أسرار أو بيانات أو نشر تطبيق.

## 5. شكل التنفيذ المقترح

استخدام App Router الموجود، مع مساحة دخول ومساحة محمية في نفس التطبيق. عرض البيانات من الخادم متى يناسب، ومكونات تفاعلية للجداول والنماذج والخريطة فقط. لا منصة CRUD عامة ولا طبقات repository إضافية.

يُضاف فقط ما يحتاجه الربط: حزم Supabase المناسبة بعد قراءة وثائق الإصدار، ومكونات UI وفق المشروع عند الحاجة؛ shadcn/ui مذكور كاتجاه منتج لكنه غير مثبت حاليًا. لا تثبيت مجموعة مكتبات كاملة مسبقًا.

البيانات العادية تعمل بهوية المستخدم وRLS؛ أي استخدام لصلاحيات خدمة يبقى على الخادم مع تحقق مستقل من المنفذ والنطاق. قوائم بفلاتر وترقيم خادمي وحد أقصى، وتجميعات SQL للمؤشرات بدل تحميل كل السجلات. البيانات الحية فقط تستخدم اشتراكات محددة؛ لا polling شامل ولا GPS history جديد.

مسارات مستهدفة: `/login`، استعادة كلمة المرور، `/overview`، `/orders` و`/orders/[id]`، `/offers`، `/drivers` وتفاصيلهم، `/verification`، `/motorcycles`، `/users`، `/offices` وتفاصيل المكتب/موظفيه، `/live`، `/reports`، `/finance`، `/roles`، `/settings`، `/audit`. الأسماء النهائية اختيار تنفيذي؛ النطاق لا يختلف.

## 6. ملف المهام التنفيذي

الأولوية: P0 أساس/أمان يمنع البناء الآمن؛ P1 ميزة لازمة لاكتمال MVP؛ P2 قبول وتشغيل قبل التسليم. حجم المهمة S صغير، M متوسط، L يحتاج تقسيمًا داخليًا؛ هذه أحجام نسبية وليست وعدًا زمنيًا.

الأدوار: **B** باك إند، **F** واجهة، **Q** قبول وتكامل. المنسق يراجع المخرجات ويغلق المهام بالدليل. علامات الاختيار وسجل التسليم يبينان الحالة الحالية؛ «يعتمد على» يعني شرط بدء الربط/القبول، مع إمكان تجهيز الواجهة المستقلة مبكرًا.

### الموجة 0 — تثبيت العقود وبيئة القبول

- [x] **ADM-01 | P0 | B/Q | M — جرد عقود الداشبورد.** مقارنة المصدر ببيئة Development عندما يصبح الاتصال متاحًا؛ تحديد migrations المطبقة فعلًا، RPCs والجداول والأعمدة ومنحها وسياساتها. الناتج جدول عقد لكل شاشة، دون إعادة اختبار ما لم يتأثر. **القبول:** لا ميزة تعتمد على اسم جدول بالمواصفات فقط، والمسودة المالية مفصولة عن العقود المقبولة. **يعتمد:** لا شيء.
- [x] **ADM-02 | P0 | B/Q | M — مصفوفة الأدوار والنطاق.** تثبيت صلاحيات Super Admin وOperations وSupport وVerification وOffice Admin/Dispatcher/Accountant، ومفاتيح الإجراءات الناقصة؛ فصل اختيار المكتب عن استحقاق الوصول. **القبول:** جدول read/write/action لكل دور مع منع اعتماد المكتب للسائق، وحالات العضويات المختلفة والحساب/المكتب المعلق. **يعتمد:** ADM-01.
- [ ] **ADM-03 | P0 | Q | S — تجهيز قبول Development.** حسابات Super Admin وموظفي المنصة ومكتبين A/B بأدوار متفاوتة وبيانات اختبار معروفة قابلة للتنظيف، وإعدادات Auth redirects والخرائط المطلوبة. **القبول:** هوية كل حساب ونطاقه معروفان، لا أسرار في الدوكس، وتسجيل أي اعتماد خارجي غير متاح. **يعتمد:** ADM-02.

### الموجة 1 — الدخول والصلاحيات والتدقيق

- [ ] **ADM-04 | P0 | B | L — سياق وصلاحيات إدارة موثوقة.** قراءة جلسة المستخدم وصلاحياته ونطاقاته بعقد محدود، واستكمال تفويض موظفي المنصة عبر migration وعقود RPC دون كسر helpers الحالية. يشمل صراحة استبدال بوابة Super Admin الحصرية في review_* وadmin_safety_override بتفويض الإجراء الموافق لمصفوفة الأدوار، لا منح الصلاحية لكل STAFF. فحص جميع قراءات/عمليات الداشبورد الجديدة وStorage. **القبول:** اختبار API/SQL إيجابي وسلبي لكل من Verification/Operations/Support والأدوار الأخرى، رفض CUSTOMER/DRIVER، رفض صلاحية مكتب B داخل A، وعدم استمرار صلاحيات حساب معلق. **يعتمد:** ADM-02.
- [ ] **ADM-05 | P0 | B | M — سجل تدقيق مشترك.** سجل محمي للمنفذ وصلاحياته/مكتبه ونوع الكيان ومعرّفه والإجراء والسبب والتوقيت وقبل/بعد؛ إدراجه داخل معاملة التغيير. تقليل البيانات الشخصية وعدم تسجيل الأسرار. **القبول:** كل mutation حساس لاحق يستخدمه، والعميل لا يعدل أو يمحو الحدث، وفشل العملية لا يترك نجاحًا وهميًا. **يعتمد:** ADM-04.
- [ ] **ADM-06 | P0 | F | M — دورة المصادقة.** دخول Email/Password وخروج واستعادة كلمة المرور، إدارة الجلسة والتحقق الخادمي للمسارات والإجراءات، وحالات انتهاء الجلسة/عدم الصلاحية/تعليق الحساب. **القبول:** فتح رابط محمي مباشرة يفشل لغير المخول، تحديث الصفحة يحفظ الجلسة الصحيحة، والخروج وتبديل المستخدم لا يكشفان بيانات المستخدم السابق. **يعتمد:** ADM-04.
- [ ] **ADM-07 | P1 | F | M — هيكل الواجهة.** هوية بيكو، Cairo، RTL، sidebar وتنقل واعٍ بالصلاحيات، بيان النطاق الحالي، عنوان ومسار تنقل وجداول وفلاتر ونماذج وحالات loading/empty/error/forbidden. **القبول:** desktop/tablet صالحان؛ لوحة المفاتيح والتركيز والحوارات سليمة؛ عدم وجود روابط نجاح شكلية. **يعتمد:** ADM-06؛ يسمح بتجهيز المكونات قبله.
- [ ] **ADM-08 | P0 | B/F | L — الأدوار وموظفو الإدارة.** إنشاء/تسمية دور، تعديل صلاحياته، إسناد دور منصة أو مكتب، دورة إنشاء/دعوة موظف عبر مسار خادمي موثوق وبمصادقة Email/Password. **القبول:** لا رفع ذاتي للصلاحيات، لا إسناد دور منصة من مكتب، منع فقدان آخر وصول إداري صالح، تدقيق التعديلات وتطبيق سحب الصلاحية على الطلب التالي. **يعتمد:** ADM-04/05/06/07.

### الموجة 2 — المكاتب والسائقون والمركبات والتحقق

- [ ] **ADM-10 | P1 | B/F | M — موظفو المكتب.** قائمة وإنشاء/دعوة وتعيين دور وتفعيل/تعليق عضوية وفق صلاحية إدارة الموظفين المحددة في ADM-02. **القبول:** عضوية المكتب المستهدف هي مصدر التفويض؛ رفض تعديل مكتب آخر أو منح دور منصة؛ عدم تسريب بيانات موظفي منصة/مكاتب أخرى. **يعتمد:** ADM-08/09.

- [ ] **ADM-12 | P1 | B/F | M — المركبات.** قائمة وتفاصيل وإنشاء/تعديل وربط بالسائق والمكتب وصور ومستندات، وحالة التشغيل منفصلة عن اعتماد المستندات. **القبول:** لا ربط عبر مكتب آخر أو تغيير مركبة رحلة قائمة؛ التعديلات التي تستلزم مراجعة تحافظ على شروط الأهلية؛ نفس مسار مراجعة ADM-14. **يعتمد:** ADM-11.
- [ ] **ADM-13 | P0 | B/F | M — الوصول الآمن للمستندات.** معاينة الملفات الخاصة بروابط قصيرة العمر، تحقق نطاق المستخدم، رفع/استبدال بالنيابة فقط لمن تسمح صلاحياته، والتحقق من النوع والحجم. **القبول:** رفض ملف مكتب آخر حتى بمعرفة path، لا bucket عام، ولا كشف روابط/ملفات في السجلات؛ المستند البديل يظل PENDING. **يعتمد:** ADM-04/11/12.

### الموجة 3 — الطلبات والعروض والعملاء والتدخل التشغيلي

- [ ] **ADM-17 | P1 | B/F | M — قائمة الطلبات.** ترقيم خادمي وبحث وفلاتر تاريخ/حالة/خدمة/مكتب/سائق/عميل؛ عرض أسعار العميل والاتفاق والتواريخ والدفع Cash. **القبول:** النطاق يطبق قبل النتائج والعدد؛ لا تنزيل كل الطلبات؛ استمرار الفلاتر عند العودة من التفاصيل؛ الحالات الفارغة منفصلة عن فشل الشبكة. **يعتمد:** ADM-04/07.
- [ ] **ADM-18 | P1 | B/F | L — تفاصيل الطلب وشاشة العروض.** timeline من order_events، المسار، العميل والسائق والمركبة ومكتب الطلب التاريخي والأسعار والتوقيت والإلغاء وعروض الطلب. تشمل أيضًا شاشة `/offers` مستقلة عابرة للطلبات بالنطاق المصرح: الطلب والسائق والمكتب والمبلغ والحالة والتوقيت والفائز، مع بحث وفلاتر وترقيم خادمي وروابط التفاصيل. **القبول:** الربط بـselected_offer_id لا باستنتاج الواجهة؛ نطاق القائمة والعدد والتفاصيل متطابق؛ بيانات شخصية بالقدر المطلوب؛ لا كشف كود تأكيد Delivery أو أسراره ولا أزرار اختيار عرض نيابة عن العميل. **يعتمد:** ADM-17.
- [ ] **ADM-19 | P0 | B/F | L — تدخلات الطلبات الموثوقة.** إلغاء إداري محدد وعمليات تصحيح محدودة ومراجعة `admin_safety_override` الحالية؛ صلاحيات منفصلة وسبب وتأكيد وقبل/بعد. **القبول:** رفض انتقال غير مشروع أو تغيير agreed_price بعد التعيين؛ إلغاء الطوارئ لا يضيف رسومًا؛ تكرار/تزامن الطلب لا يكرر الإنجاز/العمولة؛ كل تدخل يظهر في timeline والتدقيق. **يعتمد:** ADM-05/18؛ تغييرات الحقول غير المحسومة تُحصر قبل تنفيذها ولا تُفتح كمحرر عام.
- [ ] **ADM-20 | P1 | B/F | M — العملاء والمراجعة التشغيلية.** قائمة وملف وتاريخ طلبات ومؤشرات مكتملة/ملغاة، تعليق/استعادة بصلاحية وسبب، وعرض حالات cooldown/المراجعة إذا كان لها مصدر معتمد. **القبول:** لا وصول شامل للعملاء لموظف مكتب؛ لا محو تاريخ؛ حالات غير منفذة تظهر اعتمادًا ناقصًا لا أرقامًا مختلقة؛ لا نظام تذاكر جديد. **يعتمد:** ADM-05/07/17.

### الموجة 4 — التشغيل المباشر والمؤشرات والتقارير

- [ ] **ADM-21 | P0 | B | M — عقد بيانات التشغيل المباشر.** إسقاط محدود للأوامر النشطة والسائقين المصرح بهم وآخر الموقع ودقته وتوقيته؛ اشتراك معزول للنطاق وتنظيفه عند الخروج/تبديل المكتب. **القبول:** اختبار Office A/B على القراءة والأحداث؛ المواقع القديمة مميزة؛ لا فتح جدول GPS كله ولا إعادة استخدام RPC مالك العميل للتحايل على النطاق. **يعتمد:** ADM-04/17.
- [ ] **ADM-22 | P1 | F | M — خريطة التشغيل.** خريطة وقائمة مرتبطة، مواقع السائقين والمسار/نقاط الطلب المسموح بها، فلاتر المكتب للمنصة والخدمة والحالة وروابط التفاصيل. **القبول:** تحميل وفشل الخريطة وفقد الاتصال واسترجاعه، عمر آخر تحديث ظاهر؛ لا استدعاء route/ETA لكل سائق ولا علامات وهمية. **يعتمد:** ADM-21/18 وإعداد مفتاح Maps المقيد للويب.
- [ ] **ADM-23 | P1 | B/F | M — Overview.** إجمالي اليوم والنشط والمزايدة والمكتمل والملغى، السائقون online/active/type، المكاتب النشطة، إجمالي قيمة الطلبات المكتملة حسب صلاحية المالية. **القبول:** تجميع خادمي بالنطاق والتاريخ وحدود اليوم المتفق عليها، دون خلط Gross بالإيراد/العمولة؛ office لا يرى أرقام المنصة. **يعتمد:** ADM-04/07/17؛ الأرقام المالية تعتمد ADM-25 عند عرض عمولة.

### الموجة 5 — المالية المحدودة والإعدادات وسجل التدقيق

- [ ] **ADM-25 | P0 | B/Q | L — قبول الأساس المالي D07.** مراجعة المسودة الحالية واختبار snapshots/ledger/credit وعرض فقدان البيانات القديمة، وعدم إعادة تطبيق migrations سابقة. **القبول:** حدود promotion منذ أول تفعيل، الحساب والتقريب، انتقال مكتب السائق، exactly-once عند الإنجاز بما فيه override، لا قيد رجعي للطلبات القديمة، RLS ومنح صحيحة. **يعتمد:** ADM-01/05؛ تحتاج بيئة SQL Development.
- [ ] **ADM-26 | P1 | B/F | M — قراءة المالية.** واجهة gross/commission/net للمستقل وعمولة المنصة على المكتب، commission_due/platform_balance مع الفترة ومصدر القيم؛ صلاحية finance.view منفصلة. **القبول:** لا حساب صافي راتب Office Driver؛ لا اعتبار UNKNOWN صفرًا؛ إجماليات متسقة ولا أخذ آخر 50 رحلة كإجمالي تاريخي؛ مكتب A لا يقرأ B. **يعتمد:** ADM-25/07.
- [ ] **ADM-27 | P0 | B/F | M — إثبات الشحن اليدوي للمستقل.** مسار موثوق لمبلغ ومرجع تحويل وسبب، صلاحية كتابة محددة؛ الاستفادة من عقد الخدمة الحالي خلف تحقق خادمي. **القبول:** actor من الجلسة لا من مدخل متصفح، منع المبلغ غير الصالح، منع قيد مكرر لنفس الطلب/المرجع، معالجة نتيجة الشبكة غير المؤكدة، وتدقيق. **يعتمد:** ADM-25/26.
- [ ] **ADM-28 | P1 | B/F | M — تسوية المكتب الأسبوعية المحدودة.** كشف أسبوعي من حقائق الرحلات والعمولة وإثبات التسوية/التحصيل اليدوي بالمبلغ والمرجع والمنفذ، دون محاسبة أو payroll متقدم. **القبول:** مطابقة الإجماليات بالمصدر وعدم حساب التحصيل مرتين، فصل المستحق عن المحصل، تاريخ المكتب لا يتغير بنقل السائق؛ تعريف الفترة والتصحيحات التشغيلية يوثق قبل الكتابة. **يعتمد:** ADM-25/26/09.
- [ ] **ADM-29 | P0 | B/F | L — الإعدادات المسموح بها.** schema محدود للمفاتيح وقيمها وصلاحياتها، قراءة/تعديل مدقق للخدمات والتسعير والعمولات والفترات والوثائق والتتبع والإشعارات حسب العقود الفعلية. يشمل جرد dispatch radii/step، انتهاء المزايدة والعروض، حد 70%، أسباب/حدود الإلغاء ومتطلبات المستندات؛ القيم التي جمدها المنتج تعرض للقراءة ولا تُفتح للتغيير لمجرد ورودها في قائمة إعدادات قديمة. **القبول:** تغيير الإعداد المسموح يغير مستهلِكه فعلًا، القيمة غير الصالحة ترفض خادميًا، لا تعديل أسرار من الواجهة، والتغيير لا يعيد احتساب أسعار/عمولات تاريخية. **يعتمد:** ADM-05/07/25 للحقول المالية.
- [ ] **ADM-30 | P1 | B/F | M — مناطق التشغيل.** قائمة وعرض حدود وتفعيل/تعطيل وتعديل نطاقات PostGIS مع تحقق هندسي، بدءًا بالمناطق التجريبية المعتمدة. **القبول:** شكل صالح وحدود ظاهرة، لا اختراع حدود سوق غير معتمدة؛ تعديل المنطقة يؤثر على طلب جديد ولا يفسد رحلة قائمة؛ السبب والتدقيق. **يعتمد:** ADM-29 وإعداد الخرائط؛ يمكن تجهيز القراءة دون تحرير الحدود.

### الموجة 6 — القبول والتسليم

- [ ] **ADM-32 | P0 | Q/B | M — اختبار أمان موجه.** Super Admin وموظفو المنصة وأدوار المكتبين وعضوية متعددة مختلطة، مستخدم معلق ومكتب معلق وعميل/سائق ومجهول. اختبر الروابط وطلبات API مباشرة، ملفات Storage والتجميعات وRealtime والمنح. **القبول:** لا عبور نطاق أو صلاحية، ولا مفتاح خدمة في المتصفح، وسحب الصلاحية يمنع العملية الجديدة. **يعتمد:** الموجات المنفذة؛ يتجزأ حسب العقود المتغيرة ولا ينتظر النهاية لإصلاح الخطر.
- [ ] **ADM-33 | P1 | Q/F | M — قبول المتصفح.** تسجيل دخول → مكتب/سائق → مستندات/اعتماد → طلب/عروض/timeline → تدخل مخول → تقرير/مالية → إعداد → audit؛ تكرار المسارات المناسبة بمكتب A وB. **القبول:** عمليات فعلية ونتائج محفوظة مع هوية الدور، RTL وتابلت وسطح مكتب، keyboard/focus وloading/empty/error/retry، لا بيانات تجريبية ثابتة في مسار التشغيل. **يعتمد:** ADM-03 والشاشات المعنية.
- [ ] **ADM-34 | P1 | Q/B/F | M — الاسترداد والتزامن والتكلفة.** إعادة إرسال عملية بعد timeout، اعتماد مستند تغير، نقل مكتب/تعليق بالتزامن مع عملية، تبديل جلسة/مكتب أثناء تحميل، انقطاع وإعادة اتصال. **القبول:** لا تكرار أثر مالي/تشغيلي ولا تسرب بيانات متأخرة؛ طلبات محدودة وترقيم خادمي واشتراكات منظفة، دون N+1 واضح. **يعتمد:** العقود المتغيرة فقط.
- [ ] **ADM-35 | P2 | Q/F | M — حزمة النشر والتشغيل.** README محدث للتهيئة، متغيرات عامة/خادمية واضحة، إعدادات redirects وHTTPS ومفتاح Maps المقيد، خطوات إنشاء أول مشرف بأمان، جدولة انتهاء المستندات، سجل أخطاء منقح وخطة رجوع. **القبول:** lint/build مرة بعد اكتمال تغيير الداشبورد، تشغيل build فعلي وsmoke للدخول ودور مكتب، لا أسرار؛ النشر الفعلي حسب التفويض، وحسم متطلب MFA للمشرف قبل الإطلاق العام دون اعتباره منفذًا. **يعتمد:** ADM-32/33/34.
- [ ] **ADM-36 | P1 | Q | S — إغلاق سجل التسليم.** تحديث حالة كل مهمة ودليلها والعوائق المتبقية وروابط الدوكس المتقادمة. **القبول:** لا مهمة DONE دون معيارها؛ فصل اكتمل المصدر عن قبول Development وعن public launch؛ تسليم قائمة blockers بأصحابها. **يعتمد:** جميع مهام MVP.

## 8. مسار الإنجاز والعوائق

المسار الحرج: **عقود ونطاق → تفويض وتدقيق → دخول وهيكل → دورة سائق ومكتب وتحقيق → طلب وتدخل تشغيلي → مالية وإعدادات → قبول ونشر**. التقارير والخريطة تنفذان بالتوازي عند اكتمال عقود قراءتهما.

نقطة التسليم الأولى المفيدة: مشرف يدخل، يرى طلب سائق حقيقي، يعاين مستنداته، يعتمد/يرفض، ويظهر الحدث في سجل التدقيق؛ موظف المكتب يرى نطاقه ويُمنع من الاعتماد. هذه نهاية أول مسار تشغيلي وليست نهاية الداشبورد.

| الاعتماد | يؤثر على | ما يمكن إنجازه قبله |
|---|---|---|
| اتصال Development ومطابقة migrations | قبول RLS/RPC والبيانات الحقيقية والمالية | الهيكل وكتابة المصدر ومراجعة العقود |
| حسابات أدوار ومكتبين | قبول التدفقات والعزل | اختبارات محددة وتهيئة سيناريوهات |
| إعداد Maps للويب | قبول الخريطة وحدود المناطق | القائمة التشغيلية وحالات الخريطة |
| إعداد البريد وredirects | قبول استعادة/تهيئة حسابات الموظفين | واجهات المصادقة والتحقق الخادمي |
| حسم المتطلبات القانونية للوثائق وRide | الإطلاق العام ومتطلبات بعض المستندات | بقية التطوير والتحقق المعتمد |
| تهيئة scheduler والنشر | قبول التشغيل العام | كل مسارات الإدارة المحلية/Development |

لا حاجة لإيقاف كل التنفيذ عند اعتماد خارجي واحد. يسجل المتأثر `BLOCKED` ويستمر العمل المستقل. لا نعيد السؤال عن قواعد سبق تجميدها؛ أي اختيار جديد يغير الأعمال يوثق قبل تنفيذه.
